# هم‌سفر (HamSafar) 🧭

**سامانه جامع گردشگری چند-نقشه‌ای** — هر شرکت گردشگری یک نسخه مستقل روی سرور خودش اجرا می‌کند و از طریق **API فدراسیون بلادرنگ** با شرکت‌های دیگر همکاری می‌کند.

> بدون هیچ وابستگی خارجی — فقط Node.js ≥ 22.5 (`node:sqlite` و وب‌سرور داخلی). نه npm install، نه Docker الزامی، نه دیتابیس جداگانه.

---

## چرا هم‌سفر؟

| ویژگی | توضیح |
|---|---|
| 🏢 **استقرار مستقل** | هر شرکت داده، کاربران، قیمت‌ها و برند خودش را روی سرور خودش دارد |
| 🌐 **فدراسیون بلادرنگ** | شرکت‌هایی که هم‌سفر دارند با API امضاشده (HMAC) همدیگر را می‌بینند و اتمیک معامله می‌کنند |
| 🧳 **پنل تامین‌کننده/چارتر** | عرضه ظرفیت (صندلی اتوبوس/پرواز/قطار، اتاق هتل...)، **انتقال مالکیت تضمینی**، فروش عمومی |
| 🎒 **پنل پکیج‌ساز** | ترکیب اجزای خدمت از بازار یا موجودی خودی → تور با تاریخ‌های اعزام و ظرفیت |
| 🤝 **پنل واسطه** | فروش خدمات و تورهای دیگران با کمیسیون خودکار؛ بدون مالکیت و ریسک |
| 🛒 **سایت عمومی سئو-محور** | SSR کامل، متا، JSON-LD (TouristTrip/Offer/TravelAgency)، sitemap، صفحات مقصد، رزرو و واچر |
| 👥 **پنل ادمین/کارمند** | کاربران و نقش‌ها، مالی و تسویه، گزارش‌ها، لاگ ممیزی، مدیریت فدراسیون |
| 🔐 **امنیت عملی** | نشست امن، CSRF روی همه فرم‌ها، RBAC، هش scrypt، امضای HMAC فدراسیون، Idempotency |

## معماری در یک نگاه

```
شرکت الف (سرور مستقل)                شرکت ب (سرور مستقل)
┌─────────────────────────┐         ┌─────────────────────────┐
│  سایت عمومی (سئو)        │         │  سایت عمومی (سئو)        │
│  پنل‌ها: ادمین/کارمند/    │         │  پنل‌ها: ...             │
│  تامین‌کننده/پکیج‌ساز/واسطه│         │                         │
│  SQLite (WAL)            │◀──API──▶│  SQLite (WAL)            │
│  /fed/v1 (HMAC+Idempot.) │  بلادرنگ│  /fed/v1 (HMAC+Idempot.) │
└─────────────────────────┘         └─────────────────────────┘
```

جریان پول و مالکیت:
- **تامین‌کننده** ظرفیت اولیه را می‌سازد و «آفر» باز می‌کند (بازار داخلی، سایت عمومی، فدراسیون).
- **انتقال مالکیت تضمینی**: کل یا بخشی از ظرفیت آفر یک‌جا به همکار دیگر منتقل می‌شود؛ معامله در دفتر حساب هر دو طرف ثبت و مالکیت جابه‌جا می‌شود.
- **واسطه** بدون مالکیت می‌فروشد؛ حاشیه قیمت (یا ۸٪ تور) به‌عنوان کمیسیون در دفتر حسابش ثبت می‌شود.
- **فدراسیون**: واسطه شرکت ب آفر شرکت الف را در «بازار فدراسیون» می‌بیند (کش کاتالوگ) و رزرو می‌زند؛ رزرو اتمیک روی سرور الف ثبت، ظرفیت همان لحظه کسر، و تراز بین دو شرکت به‌روز می‌شود.

## اجرای سریع (۳ دقیقه)

```bash
# پیش‌نیاز: Node.js ≥ 22.5
cp .env.example .env          # ویرایش کنید: نام شرکت، slug، آدرس
node scripts/seed.js --reset  # داده نمونه (اختیاری)
node server.js                # → http://localhost:3000
```

اولین اجرا بدون seed: مدیر پیش‌فرض `admin@<slug>.ir` با رمز `admin1234` ساخته می‌شود (بلافاصله بازنشانی کنید).

### حساب‌های دمو (بعد از seed)

| نقش | ورود | رمز |
|---|---|---|
| مدیر | admin@demo-travel.ir | admin1234 |
| کارمند | sara@demo-travel.ir | sara1234 |
| تامین‌کننده (اتوبوس) | bus@demo-travel.ir | bus1234 |
| تامین‌کننده (هتل) | hotel@demo-travel.ir | hotel1234 |
| تامین‌کننده (پرواز) | air@demo-travel.ir | air1234 |
| پکیج‌ساز | mahdi@demo-travel.ir | mahdi1234 |
| واسطه | maryam@demo-travel.ir | maryam1234 |

مشتریان با موبایل + کد یک‌بارمصرف ثبت‌نام می‌کنند (در دمو کد در پاسخ نمایش داده می‌شود).

## تست‌ها

```bash
node test/run.js             # ۲۴ تست واحد + ۳۶ تست E2E
```

سناریوی E2E: دو شرکت مستقل روی دو پورت بالا می‌آیند؛ تامین‌کننده الف آفر می‌سازد، ادمین ب همتا می‌شود، واسطه ب از بازار فدرال رزرو اتمیک می‌زند؛ ظرفیت، کمیسیون، idempotency، CSRF و رد ظرفیت ناکافی بررسی می‌شود.

## فدراسیون چطور وصل می‌شود؟

1. ادمین شرکت الف: پنل ادمین ← فدراسیون ← «همکار جدید» → نام، آدرس API شرکت ب، کلیدی که ب به شما داده، و **کلید ما برای آن‌ها** (تولید خودکار) را ثبت کنید.
2. ادمین شرکت ب همان کار را با آدرس و کلید الف انجام می‌دهد.
3. واسطه/پکیج‌ساز ب: بازار فدراسیون ← همگام‌سازی → کاتالوگ الف را می‌بیند و رزرو می‌زند.

## اصل میانه (چه هست، چه نیست)

**هست:** موجودی و آفر تضمینی، انتقال مالکیت، پکیج‌سازی، فروش واسطه‌ای با کمیسیون، دفتر حساب و تسویه، سایت سئو-محور با واچر، فدراسیون بلادرنگ با idempotency، لاگ ممیزی، OTP مشتری.

**نیست (عمداً):** درگاه پرداخت آنلاین (جای اتصال مشخص است: `confirmBooking`)، چند-ارزی، پیامک واقعی (جای آن در `/register` مشخص است)، کش Redis، ریز خدمات CRM. این‌ها بدون تغییر معماری اضافه می‌شوند.
